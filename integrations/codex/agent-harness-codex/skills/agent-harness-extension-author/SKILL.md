# Agent Harness Extension Author

Make changes in the independent `agent-harness` source repository. Consumer repositories may supply a sanitized reproduction but must not receive a copied Harness implementation.

First classify the change as Kernel, Profile, plugin, tool integration, Skill adapter, or legacy compatibility. Keep the Kernel free of business, provider, model, language, and build-system names. Prefer a declarative Project Descriptor or Profile; use project-specific code only in an explicitly installed Extension Pack.

An Extension Pack has a stable lowercase ID, semantic version, immutable artifact digest, and explicit Profiles, plugin factories, recovery importers, or build-time operations. Plugins return only versioned Intent, Event, or Receipt envelopes and never mutate Authority. Process-capable plugins must declare managed outputs, budgets, retention, cleanup, and sandbox requirements.

Agent execution has two explicit modes. Every Project Descriptor explicitly selects a Prompt Codec, and every Dispatch pins its plugin ID/version plus a Prompt Contract version. A Prompt Codec deterministically compiles the immutable Dispatch Packet into the entire child-Agent prompt and returns packet and prompt digests; Operator Skills and Runtime adapters may transport that exact text but must not compose, summarize, prepend, append, translate, or repair prompt prose. Interactive Codex projects use `conversation-visible`: their Runtime must declare both `user-visible` and `host-orchestrated`, use the host's native child-Agent/delegation surface, expose an inspectable task reference and progress, and must not request `process.spawn`. Lease receipts bind `agentId`, `dispatchId`, `packetDigest`, `promptDigest`, Prompt Codec identity, and Prompt Contract version and require a matching trusted-host attestation over both digests; raw CLI JSON and direct Kernel/PluginHost invocation are not valid host proof. At least one fresh host heartbeat is required before result submission. If Prompt compilation, the visible host adapter, attestor, inspection surface, or heartbeat path is unavailable, fail closed; never improvise a prompt or fall back to `codex exec`, another Agent CLI, a hidden process, or an unrelated standalone task. A process-backed Agent Runtime must declare `headless` and may be selected only when both the Descriptor explicitly chooses `agentExecutionMode: headless` and the user explicitly requests CI or unattended automation; never infer one from the Runtime ID or the other condition. Deterministic Gate, build, test, packaging, and short Harness control commands may use managed processes, but they are not Agent Runtimes and must require a live observer that exposes start, progress/output, completion, and interruption state to the operator.

Register Extension artifacts beneath the standalone control root. Do not load changed code under an existing installation receipt, and do not search a consumer repository for executable extensions.

Add a regression test at the narrowest owning layer. Prompt changes must prove deterministic compilation, exact Packet/Prompt digest binding, required contract identity, and rejection of missing, modified, or ad-hoc prompts. Runtime changes must prove that conversation-visible projects reject process-backed or non-host-orchestrated Runtimes, direct execution-plugin and Kernel binding bypasses fail, visible Lease receipts and host attestations bind Agent/Dispatch/packet/prompt identities, fresh heartbeat is required, missing host delegation fails closed, headless is never inferred, and no process fallback occurs. Process Gate tests must prove execution is rejected without a progress observer. Run the full project, conformance, canary, packaged-install, path-boundary, and residue checks before release. Do not silently replace an already published artifact: fix unreleased V1.0.0 work under a new commit digest, and use a patch version after V1.0.0 is published.

Read [references/extension-contract.md](references/extension-contract.md) when implementing or reviewing an Extension Pack.
