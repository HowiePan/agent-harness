## 定位

V1.0.0 是首个且唯一的初始正式版本。项目不发布 V0.x 或其他中间小版本；W0-W9 只是内部开发和验证 Wave。

## 核心交付

- 通用 Authority Kernel、外部 Storage、事务、Evidence、Recovery 和 Receipt；
- 中立默认组合、Authority 管理的持久 Extension Registry、Project Descriptor 对 Harness/Extension 的 ID/版本/完整制品摘要绑定；
- Project Descriptor 输入/Registry 记录双 Schema、公共无依赖校验器、生成器示例 round-trip 与持久字段回灌拒绝；
- 工具无关 Operator Contract、Codex Operator Skill 与 Extension Author Skill；
- 脱敏 Defect Bundle 和禁止可执行内容的 Legacy Recovery Capsule；
- Scheduler、Agent Runtime、Model Router、Tool Broker、Codec、Gate、Artifact、Storage 与 OS Sandbox Plugin SDK；
- 进程插件受管输出声明、运行中字节/文件预算、保留策略和摘要绑定清理 Receipt；
- Codex 与至少一个非 Codex Runtime；
- 真实非交互 Codex CLI Coordinator、可替换 Model Router 和 Project Gate Runner；
- 通用 Workflow Primitive、Feature 调度、Profile 和 Project Registry；
- W1 前完成 CardWorld Engine、Collection 与 V1.0.0 目标模型的 G0 双轨差异审计；
- CardWorld Engine Delivery Profile；
- Collection Batch Production Profile 与 Harness 控制面优化；
- 两个旧 Harness 的独立 Legacy Importer 和 Hard Recovery；
- 三个不同类型项目的零驻留 Canary；
- 完整运维、迁移、回滚和用户切换审批包。

## 统一决定

- Engine 与 Collection 使用不同业务 Profile，不共享业务状态机；
- 两者以 Feature 为 Agent 调度单元，Feature 内 Step 串行；
- Collection 的批间 Barrier 与批内 Feature Graph 同时存在；
- 两者当前质量周期都要求 P0-P3 全量关闭；
- known debt 不作为当前版本准出通道；
- Runtime、工具和模型与 Profile 正交；
- 业务仓默认零 Harness 驻留。

## 实施 Wave

```text
W0 独立项目与冻结基线
→ G0 双轨差异审计 Gate
→ W1 协议与 Conformance
→ W2 Authority Kernel 与 Storage
→ W3 Plugin SDK
→ W4 参考控制面与 Runtime
→ W5 Workflow Primitive 与 Profile
→ W6 CardWorld Profile + Hard Recovery
→ W7 Collection 优化 + Hard Recovery
→ W8 非 Codex Provider + 系统加固
→ W9 零驻留切换 + V1.0.0 准出
```

W6 与 W7 在 W5 后可以并行，但 W8、W9 必须等待二者全部完成。

G0 是正式硬前置而非实施 Wave：必须以代码、Schema、文档和获准读取的运行事实形成差异矩阵、行为处置、架构归属、拒绝继承清单和 Golden Scenario。G0 未通过时不得启动 W1。详细合同见 [G0 双轨差异审计 Gate](../gates/dual-track-differential-audit.md)。
