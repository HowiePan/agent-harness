## 人工边界复核

- Kernel 源码禁止 CardWorld、Collection、Game、Batch、Codex、Rust 和 WASM 专名；
- Runtime、工具和模型通过插件合同接入；
- Project Descriptor 必须显式选择 `conversation-visible` 或 `headless`；CardWorld/Collection 交互式默认使用 `codex-conversation-runtime`，其他 Runtime 不会自动推断 headless；进程 Agent Runtime 只允许用户请求与 Descriptor 双重显式 headless；
- 每个交互式 Dispatch 必须由当前宿主创建可见子 Agent；可信宿主证明把 Agent、Dispatch、Packet 与 inspect reference 绑定，提交前必须有新鲜 heartbeat。缺少原生委派、证明或观察能力时 attention-required，禁止原始 CLI Receipt、`codex exec`、后台 Agent CLI 或独立任务兜底；
- 默认入口与根包导出不加载 Consumer、供应商 Runtime 或 Legacy Importer；Extension Pack 显式安装并绑定精确版本；
- Extension plugin factory 不获得 Authority/Evidence Store，只得到受控 Control/Data Root、项目解析器和时钟；
- npm 包不能把自身 `node_modules` 目录隐式当作数据根；独立控制根由安装标记绑定 Runtime 相对位置；
- Extension Registry 持久保存入口、版本和完整制品摘要；安装变更经 Authority/Revision/Command 审批，跨进程重启自动加载，任一清单文件漂移会在执行扩展前拒绝；
- Descriptor 配置输入与 Registry 持久记录使用独立 Schema；生成的 Engine/Collection 输入、持久化 round-trip 和 additional-property/protocol override 拒绝均进入 `npm run check` 与自动测试；
- Consumer 选择其他 Runtime 时不会继续声明 Codex Extension；
- Harness 版本与发布制品 SHA-256 可由 Project Descriptor 精确绑定；未配置 Model Route 时 fail-closed；
- Engine 与 Collection 分别使用 Profile，不共享业务状态机；
- 两者均以 Feature 为调度单元，Collection 同时保留批间 Barrier；
- 当前质量周期 P0-P3 全部阻断；
- 运行状态、Extension Registry、Runtime/Gate 临时目录、npm 缓存/日志和测试/clean-room 夹具只写 Standalone Control Root 内部；越界 `dataRoot`、底层 Store/Runtime root 以及 symlink/Windows junction 穿越均被拒绝，子进程临时环境不可被项目配置覆盖；`doctor` 零写入，成功、失败与校验拒绝路径均清理临时目录；
- 本地进程插件必须声明受管输出目录、文件/字节预算和保留策略；确定性 Gate 在启动前强制实时观察器，运行中超限会终止，清理 Receipt 会固化进 Gate/Runtime Evidence；OS Sandbox 支持 disabled/optional/required，required 缺少 Provider 时 fail-closed；
- 历史上两个现场只执行过只读 assessment；本轮复核时冻结的两个旧状态根已经不存在，因而无法生成新的 assessment 或真实 Capsule；
