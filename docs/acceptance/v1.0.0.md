## 自动验收

以下命令是候选准出的权威复验入口：

```powershell
npm run build:release-metadata
npm run check
npm test
npm run test:conformance
npm run test:canary
npm run check:clean-room
npm run pack:dry-run
node scripts/check-residue.mjs
node bin/agent-harness.mjs doctor --data-root .tmp/doctor
```

本地最终结果：`npm test` 70/70 通过；零驻留 Canary 3/3 通过；clean-room 70/70 通过，并从实际 npm tarball 安装到专用 Standalone Control Root 后完成中立根包探针、Authority 批准的 Extension 安装和第二进程恢复。测试包含 Descriptor 输入/持久记录 Schema round-trip、协议字段覆盖拒绝、Harness/Extension 完整制品校验和 symlink/Windows junction 防逃逸；Codex 插件及其中两个 Skill 使用官方结构校验；隔离 Runtime 验证 10 个游戏 Feature 的物理并发与安全合并；残留扫描确认 `.tmp`、缓存、EXE 与 PDB 均不存在。

测试覆盖 expected revision、command idempotency、事务恢复、Feature DAG/冲突、公平调度、工作区快照与越权遗漏、Evidence、Gate cache、P0-P3、普通/硬恢复、只读 recovery plan、恢复快照与 rollback、Artifact rebase、恶意插件、真实非交互 Codex CLI 协议探针、非 Codex Runtime Conformance、可替换 Model Router、CardWorld/Collection Consumer 编译器、Collection 共享能力/批次 Barrier/10 游戏逻辑并行、冻结 Legacy Characterization、1000 Feature Graph 和三个零驻留 Canary。

## 人工边界复核

- Kernel 源码禁止 CardWorld、Collection、Game、Batch、Codex、Rust 和 WASM 专名；
- Runtime、工具和模型通过插件合同接入；
- 默认入口与根包导出不加载 Consumer、供应商 Runtime 或 Legacy Importer；Extension Pack 显式安装并绑定精确版本；
- Extension plugin factory 不获得 Authority/Evidence Store，只得到受控 Control/Data Root、项目解析器和时钟；
- npm 包不能把自身 `node_modules` 目录隐式当作数据根；独立控制根由安装标记绑定 Runtime 相对位置；
- Extension Registry 持久保存入口、版本和完整制品摘要；安装变更经 Authority/Revision/Command 审批，跨进程重启自动加载，任一清单文件漂移会在执行扩展前拒绝；
- Descriptor 配置输入与 Registry 持久记录使用独立 Schema；生成的 Engine/Collection 输入、持久化 round-trip 和 additional-property/protocol override 拒绝均进入 `npm run check` 与自动测试；
- Consumer 选择其他 Runtime 时不会继续声明 Codex Extension；
- Harness 版本与发布制品 SHA-256 可由 Project Descriptor 精确绑定；未配置 Model Route 时 fail-closed；
- Engine 与 Collection 分别使用 Profile，不共享业务状态机；
- 两者均以 Feature 为调度单元，Collection 同时保留批间 Barrier；
- 当前质量周期 P0-P3 全部阻断；
- 运行状态、Extension Registry、Runtime/Gate 临时目录、npm 缓存/日志和测试/clean-room 夹具只写 Standalone Control Root 内部；越界 `dataRoot`、底层 Store/Runtime root 以及 symlink/Windows junction 穿越均被拒绝，子进程临时环境不可被项目配置覆盖；`doctor` 零写入，成功、失败与校验拒绝路径均清理临时目录；
- 本地进程插件必须声明受管输出目录、文件/字节预算和保留策略；运行中超限会终止，清理 Receipt 会固化进 Gate/Runtime Evidence；OS Sandbox 支持 disabled/optional/required，required 缺少 Provider 时 fail-closed；
- 两个现场只执行了只读 assessment，没有修改旧状态；
- 合成 Recovery Capsule happy path 已验证现有摘要、容量、保留和禁止源码/脚本/EXE/DLL/PDB；一致性快照、完整复算、链接拒绝、验证结果绑定和 hard recovery 用户审批仍须按[抽离后台账](../post-extraction-register.md)修复；
- 脱敏 Defect Bundle 具备 Schema、摘要和敏感字段拒绝测试；修复只进入独立上游仓库；
- Card World → 独立 agent-harness → 新制品 → Descriptor 升级 → 原 Run 续跑/回滚的端到端维护闭环尚未演练，已登记为 [PUB-008](../post-extraction-register.md)，Collection 后续复用协议执行回归 Canary；
- Legacy 协议已冻结为脱敏 Fixture 与固定摘要，后续设计和开发不再需要旧 Harness 源码作为参考；
- 共享 Codex CLI Runtime 被安全收紧为单物理槽；Collection 默认使用隔离 Codex Runtime，10 路物理并发、changed-files 核对和按文件基线合并已有自动测试；
- 未执行 Git commit/tag、远端发布、密码学签名、真实切换或旧内容删除。

## 平台与发布说明

本地 Windows/Node 22 候选执行完整测试；GitHub Actions 配置 Windows 与 Ubuntu Node 22 复验。Linux CI 的结果只有在所有者推送独立仓库后才能形成远端证据。项目无第三方运行时依赖；release manifest 与 SPDX SBOM 由脚本确定性枚举发布内容。

## 准出结论与后续发现

V1.0.0 已达到 **Repository Extraction Ready**：即使 CardWorld 与 Collection 的旧 Harness 源码、Skill 和文档不可访问，公共项目仍可独立安装、自举、加载扩展、运行测试并继续维护，因此允许提交到独立仓库。

后续自审发现 Recovery Capsule 与 live hard recovery 的完整性和授权链仍有缺口。问题已登记在[仓库抽离后修复与验证台账](../post-extraction-register.md)的 RCV-001～RCV-006；它们不阻止仓库抽离，但阻止正式 V1.0.0 发布和生产切换。独立远端发布、真实 Recovery Capsule、rollback 和现场入口切换按 PUB/CUT 条目验证。旧 Harness 的删除只由用户决定，不属于自动准出动作。
