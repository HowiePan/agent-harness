# 项目内持续执行

## 文件权限与计划

当前配置入口为项目 `harness.json`：`schemaVersion: "1.1"` 下的 `project.fileBoundary`，包含 version、sourceRoots、sharedPaths、artifactRoots、protectedPaths。初始化、重绑和迁移均使用同一个解析器；新格式缺失或冲突拒绝。引擎显式登记 `.cardworld-local` 为 artifactRoots，不能遗漏，也不能作为生产源码目录。1.0 旧配置保留严格路径兼容，不从目录名猜测新授权。

`policy.projectFilePolicy` 由 Project Descriptor 登记并固化到 Run 与 Dispatch，不能由 Agent 结果扩大。

```json
{"version":"project-files/1","mode":"project-owned","roots":["engine","scripts/engine.ps1","docs/engine"],"protectedPaths":["engine/secrets"]}
```

根路径相对于该项目执行 checkout。Git 根目录、Git common directory、工具可写目录和父目录均不自动成为授权范围。单项目 checkout 可显式登记 `.`；多项目仓库必须登记自己的目录与必要共享文件/子目录。现有引擎适配器只登记引擎、现有引擎专用文档/脚本和配置，其他子项目不在范围内。

新策略下，Feature 的 allowedPaths/forbiddenPaths 是项目内部的规划参考；protectedPaths、只读阶段、验收、架构和用户明确禁止事项继续有效。跨参考路径修改通过 `scopeAdjustments: [{path, reason}]` 说明其与当前验收的联系；若缺少细项，Host 使用原生提交摘要自动记录原因，不能只因漏写可选解释数组中断实施。Host 核验实际变更、物理路径及链接，Kernel 记录调整事件，不仅因目录变化要求 Amend。目录之外的业务语义变化仍须经过修订判断。

源代码审核中的路径检查是合作式协议与提交门禁，不是对所有原生工具的全局文件沙箱。不能声称提交时检查能撤销先前的越权写入。

原生 Host 尚无写入前文件占用 API，因此有此策略的同一 Run 中写入 Feature 使用项目级独占调度，保持多个适中批次；不能靠提交后的文件列表冒充冲突预防。只读 Feature 保持只读和原冲突规则。跨 Run 的活动工作仍由原项目活动 Lease/Run 准入机制阻断。未配置本策略的历史 Plan 保持原严格路径语义。

## 时间、健康与资源

新执行默认 `timeoutMs: 0`，表示没有总时长截止；显式正整数表示该次操作确实要求的截止时间。观察窗口、心跳新鲜度、身份有效期和总运行时长分别处理，不能用观察窗口结束宣告任务失败。历史 Plan 已明确填写的截止时间不被静默删除，必须正式迁移或修订。

Windows Job 保留内存、CPU、进程数、输出与父进程存活保护；父宿主退出时杀死后代，主进程退出时关闭 Job 清理后代。运行中定期发出观察状态。有效进展由 Host 核验的源码变化、构建阶段、测试结果和检查点提供；日志数量、重复输出、心跳和文件时间戳不构成验收。缺少近期进展或新鲜观察只产生诊断信号，不自动超时杀死健康任务。真实终态失败进入恢复，用户停止和资源越限进入收束。

辅助脚本继续使用有界监督器与精确分片；取消时间上限不取消规模限制。大规模算法必须拆分或流式处理。

## 失败和恢复

统一复用 bounded-interruption/1 与 coordination-recovery/1：保存失败证据和检查点，收束后代，分类后在原目标与剩余额度内修复、复验、继续。项目内目录调整可纳入原修复；不得把诊断结论当作跨项目授权。真实验收失败不能转成通过，旧 Evidence 不能冒充新鲜检查。

已有受监督 Host 检查的失败回执可作为原 owner 的有界修复入口：必须绑定同一项目、Feature、Dispatch、源码、原批准命令及未漂移结果，并有原失败预算余额。该入口不消耗或重置独立诊断额度，不是通过审查；身份、权限、必需沙箱、监督器和内存余量等保护条件不足仍须停止相关动作。修复后必须执行原新鲜验收。

用户停止、跨项目/权限扩大、验收或业务合同变化、未授权受保护操作、预算耗尽、身份/证据不可信、正式恢复能力缺失，是人工介入边界。预算与诊断历史必须承接；本补丁不清零、不偷偷增加额度。

普通业务路径变化不要求 Harness 重新绑定。Harness 自身的权限/协议/Kernel 变更仍按真实影响迁移，不能关闭摘要校验来减少中断。本次包含 Kernel 和结果 Schema，属于 H4；不得向旧 Lease 注入或热改原 Plan。

Coordinator 终态仅输出小摘要与内容摘要绑定的完整结果文件引用，避免展开所有历史 Prompt/Authority 造成输出截断。引用是审计材料，不是启动或续接授权。

## 场景验证

覆盖项目内调用方修改、跨项目拒绝、路径穿越/链接、只读、修改理由、并发写入、长时间有进展、安静运行、重复日志、明确失败、资源超限、诊断及正式承接。90% 指代表性开发场景覆盖目标，不指单批交付工作量；必须记录未覆盖和 Host 权限导致的跳过，不得把目标当已实现覆盖率。
