# 基于事实的流程内恢复

`action-recovery/1` 是当前用户命令内的动作恢复合同。错误码用于检索和归因，不是穷举式发车或停止开关。现有明确的身份、权限、证据与用户停止保护继续前置生效；未知错误先实际调查，再作决定。

## 决策顺序

1. 用户停止、必要授权或合同变化优先暂停受影响动作。
2. 核验当前用户命令、Authority、工作区来源及活动效果。不能从 worker 的错误标签或建议推导权限。
3. 查询原操作的幂等命令回执；已提交且绑定一致时对账，不能重复变更。
4. 未提交操作按可信应用声明的效果语义处理：只读操作可以有界重读；原子操作保持相同输入和命令 ID，只刷新已核验的 revision；有检查点的应用操作从自己的持久检查点继续。
5. 未知副作用先观察。没有证明可重复的 Host spawn、构建进程或外部写入不能当作普通读取重放。核验不能恢复可信状态，或者确实没有受授权的下一步时，报告实际调查结果并停止。
6. 相同任务和策略在同一进展状态反复得到相同失败时止损，内部复审无可行新策略才停止。持续执行没有流程累计恢复额度；总耗时或静默本身不是失败证据。

停止一个动作不授予扩大路径、降低验收、伪造历史输入、热改 Harness 或发起新命令的权限。业务阻塞继续使用原有 source-bound 只读诊断、依赖返修和输入发现；无法取得的真实前置条件不能被自动恢复抹除。

## 操作入口

统一入口负责调查、决策、恢复预留和实际结果记录。应用声明操作语义，不声明“哪些错误可以恢复”。当前接入：

| 边界 | 机制 |
|---|---|
| 调度、心跳、Gate 结果登记、Kernel 原子更新 | 幂等回执对账，或同输入/命令 ID 的有界重试 |
| 诊断预约、评估应用、输入修复、干预登记 | 持久检查点续接；重复预约幂等返回 |
| 原生 Host wait/result | 同一 Agent/Dispatch 的受绑定重读，不重派 Agent |
| 结果验收与提交 | 原有 result-registration 检查点及原验收凭据核验；不重跑已登记的检查 |
| 其余协调器异常 | 实际只读调查当前命令、Authority、源码和效果；不把固定文字写成已经尝试 |

恢复入口不包含生命周期 start/resume/replan/implement 调用。初始准备失败没有可信 Run 时，只能报告实际可核验的信息；不能猜测另一绑定或创建 Run 来获得诊断能力。

## 身份与有限性

问题身份使用目标、逻辑归属、合同和操作语义，排除错误名称、Run ID 及观察 revision。重试保持原业务输入和幂等命令 ID，不能因新错误名称刷新额度。

恢复预留与实际成功/失败结果写入 `execution-action-recovery` Decision 和摘要绑定的 Evidence。进展摘要来自相关 Feature、Submission、Dispatch 与 Gate 状态；恢复记录本身、观察次数和 revision 增长均不算进展。

旧策略保留原预算。显式 continuous-execution 使用 `task-repetition/1`，不以 `cyclesPerProblem × diagnosticsPerCycle` 或累计协调次数停止。每个动作独立记录相同策略、关键输入及失败结果的连续重复；成功恢复中断失败串，不能把以往恢复成功当作失败消耗。派发变化、诊断完成和重复绿灯不是业务进展。正式承接保留原恢复记录与证据，换 Run 不清零；新计量视图不改写旧账本。记录无法可靠持久化时停止，不能无记录尝试。

诊断身份 v2 绑定原 Submission、当前源码及澄清关系：同一观察幂等，不同源码能够预约新诊断。新观察仍消耗同一问题的既有预算。旧诊断保留审计身份；源码变化后不能应用旧评估或当作当前待处理诊断。

## 验收与维护

故障注入覆盖：未知错误、提交后丢失响应、旧 revision、不同错误名称的相同失败、真实停止、来源变化、命令冲突、未知副作用、恢复记录承接，以及可见生命周期中的组合故障。必须验证业务完成不会重复、原验收和预算保持、必要停止仍生效。

补丁按 H0–H4 正式处理；当前命令退出后，维护只能完成验证、绑定和恢复准备。新生命周期仍须由用户发起，不能重放已退出 Coordinator。
