# 脚本规模与设备稳定性

显式启用 `continuous-execution/1` 后，使用[持续执行策略](continuous-execution.md)的资源分类、活动 Dispatch 绑定、流式输入和磁盘日志；下列固定额度继续适用于旧策略。新策略仍保留 OS Job、CPU/内存余量、单重型进程和后代清理，不能由请求自行扩大资源。

`bounded-script/1` 将辅助脚本的分片与已批准的开发批次分开。一个批次可以执行多个串行小脚本，不因此改变 Feature、验收或批准范围。不得为了合并交付而生成一个遍历、复制、展开全部计划的大脚本。

## 启动门禁与默认配额

| 项目 | Agent 辅助脚本 | Windows 确定性 Gate |
|---|---:|---:|
| 同一控制根并发 | 1，与 Gate 共用槽 | 1，与脚本共用槽 |
| 整棵进程树内存 | 512 MiB | 2 GiB |
| 主机总 CPU 硬上限 | 25% | 25% |
| 进程树活动进程数 | 4 | 16 |
| 子进程运行时间 | 默认无总时限，可显式指定截止时间 | 默认无总时限，保留批准命令的显式截止时间 |
| stdout + stderr | 1 MiB | 1 MiB |
| 每片输入 | 128 个精确文件、合计 32 MiB | 保持批准的构建输入 |
| 脚本文件 | 128 KiB | 保持批准的构建入口 |

启动前还保留至少主机内存的 20%（且至少 1 GiB）；可用内存不足“保留量 + 本次额度”时拒绝启动。线程库及构建工作线程默认设为 1。进程数限制不能替代 CPU 和内存限制。

临时文件监控逐个读取目录项，同一时刻只采样一次，不堆积扫描队列。文件数量配额包含目录项；超过字节/目录项配额即停止扫描并终止进程，`usageComplete:false` 表示计量只是超限下界，不冒充完整峰值。

Windows 监督器使用 Job Object：先创建挂起进程，配置整树内存、CPU 硬限额、进程数及 kill-on-close，再加入 Job 后恢复。无法创建/配置/加入时拒绝执行，不能退回普通 spawn。退出、超时、输出超限、监督器被终止时清理后代。原生 Agent 仍通过宿主派发；这个入口仅运行确定性脚本，禁止用它启动 Agent CLI。

当前脚本监督器只实现 Windows；其他系统拒绝脚本启动，需先提供等价 OS 实现。既有非 Windows Gate 保持原执行路径，不宣称具备这些配额。Job 不提供文件访问沙箱；输入清单不能证明任意程序实际只读这些文件。权限、允许路径和输出目录仍由原合同约束。宿主直接执行的任意工具调用无法由 Harness 事后施加 Job；新 Prompt 合同 1.6 要求脚本只能走本入口。不能把这项要求描述为宿主全局工具拦截。

原生 Gate 回归通过 `node scripts/run-supervised-tests.mjs test/<name>.test.mjs ...` 启动，最多16个精确测试文件/32 MiB；整个测试树受同样的512 MiB、25% CPU、4进程、1 MiB输出保护。测试宿主使用独立测试槽，内部被测 Gate 保持生产槽与生产 Job，不与外层占用同一槽而死锁。该入口只接受本仓库测试名，不能启动任意脚本、业务命令或 Agent Runtime；仅用于 Harness 开发验证，不是业务 Agent 的执行入口。

## 分片与续接

1. 先统计精确输入文件和字节，不执行递归全仓库扫描并一次载入。超过任一门禁就按固定 ID、文件组或记录范围拆分。
2. 每片只读本片数据，逐条处理；大型 JSON/报告用索引或固定文件引用，不把整张图反复 deep-copy 或展开为每项的完整副本。
3. 每片写自己的结果和检查点，成功后才发布该片完成状态。合并阶段只读小摘要/引用，保持原验收完整。长任务定期观察；缺少输出先诊断，不能仅因累计时长结束。`timeoutMs: 0` 表示无截止，正整数为显式截止，不能混用观察窗口与任务寿命。
4. 超限保留已有源码和成功检查点；检查失败回执，缩小分片或改为流式处理后才允许一次有界重试。相同输入/算法直接重跑、后台脱离、提高配额或绕过监督器均不可作为自动恢复。
5. `RESOURCE_SLOT_BUSY` 先等待现有任务结束。崩溃留下的锁禁止自动抢占；核验 owner 与后代均已退出后才能精确清理该锁。正常路径自动释放。

## 结构化入口

在原允许的产物路径写请求文件，再执行 `node <Harness>/scripts/run-bounded-script.mjs --request <绝对请求路径>`。请求最多 64 KiB。所有输入为绝对路径的普通文件，不接受目录、glob、符号链接和内联程序；必须包含脚本本身。命令、读写仍须在 Dispatch 授权范围内。

独立安装模式还需在请求中提供已登记的 `controlRoot`，不能把业务目录当作控制根。监督器编译和未指定的临时输出留在控制根内并清理，不写系统临时目录。脚本不能嵌套调用占用同一资源槽的 Gate；构建检查由协调器按原合同单独启动，避免互相等待。

```json
{
  "schemaVersion": "bounded-script/1",
  "cwd": "F:/project",
  "executable": "F:/tools/python.exe",
  "script": "F:/project/allowed/shard.py",
  "args": ["F:/project/allowed/shard.py", "--part", "part-01"],
  "inputs": ["F:/project/allowed/shard.py", "F:/project/allowed/part-01.json"],
  "shard": {"id": "part-01", "checkpoint": "allowed/part-01-result.json"}
}
```

回执包含片 ID、输入规模、实际输出字节、配额及退出情况。非零退出不是成功；内存分配失败可能表现为程序自身错误，不能仅凭退出码归因 OOM。单个大构建如不能适配默认 Gate 额度，应准备明确的机器资源策略评估，不能自动放宽，不能把验收删掉。

## 2026-11-05 维护边界

本次由设备卡死事件触发；事后进程查询未发现 Python/Node，未取得故障时的进程树或峰值监控，不能确认具体根因。已观察到规划辅助脚本读取并深复制展开计划，以及大制品输出；这是整改对象，不等于归因证据。

补丁涉及 Runtime/Gate/Prompt，按路径分类属于 H3，需要可信重新绑定、Coordinator 重启和新的 Run；不注入旧 Lease，不重写旧 Prompt，不恢复失联会话。既有不可变 1.5 Prompt 字节保持原样。维护测试不构成业务计划审查通过，也不自动启动 Amend。

绑定预检按单个 Authority 核验历史，只保留活动 Run 摘要，不先积累所有完整历史再过滤。生命周期与 Amend 检查需要完整历史时，逐个读取并验证原摘要，仅复用内容完全相同的不可变长字符串；对象、顺序、数值和原 Authority 字节不变，不共享可变对象，也不忽略已退役历史的完整性错误。这减少重复合同/Prompt 的内存副本，不放宽监督器额度。合成大制品回归按模式分开运行，夹具结果返回后释放已消费 packet，仍验证完整制品超过 256 KiB。

实施计划生成的历史检查仅保留完成前沿、替代身份和任务键，确认唯一未启动承接后才重读它的完整 Authority。质量目标规划保留完整 Finding、处置、前置与审查历史字段，丢弃未被质量账本消费的计划、Prompt 和源码快照副本；相同输入的质量目标摘要必须完全一致。以上均为只读决策输入，不作为 Authority 交给 Kernel，每份原记录仍逐条验证。辅助预检触及堆上限也必须停止并减少保留数据，不能提高 Job 配额。

实施执行预检同样按只读身份索引计算 lineage，仅重读与当前承接匹配或确实可能覆盖失败实施的批准规划；仍核验全部原记录，并在读回时确认 Authority 摘要未变。跨项目活动 Lease 按记录逐条核验，只保留活动归属；已结束 Host Effect 也逐条验证后释放，恢复只保留原 Run 的效果，reconcile 仅保留未收束效果。不能靠跳过其他历史的损坏记录来节约资源。

修订预检先核验全部历史的只读身份索引，再读取选定基底、活动工作和精确的重试／实施基线祖先。其他记录保留原身份、状态、活动 Lease/Dispatch、未解决 Finding 和已完成身份等阻断信息；索引不作为完整 Authority 提交给 Kernel。再次读取的祖先摘要须与索引一致。同步中的未启动实施承接检查同样只保留候选，再用完整 ID 集确认替代 Run 是否已经存在，不能忽略歧义或必要承接。

Amend 若在规划已提交、只读审查进行中遇到 H2/H3 中断，正式恢复支持核验原提交及全部候选字节、原批准基底、登记范围、当前源码和原实施基线。收束旧 Host 效果后退休旧 Run，为同一变更封存新的运行身份；新规划以候选为未批准输入，并重新审查、人工批准，不继承规划完成。恢复准备可停在 `executionStarted:false`，由后续正式命令继续。普通 Amend 重试仍不能取代活动审查。
